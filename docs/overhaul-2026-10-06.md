# The October 2026 overhaul

Work done on branch `overhaul-2026-10-06`. This page records what changed, why,
and what still needs a human.

## Going back to the earlier version

The state just before the overhaul is tagged **`baseline-2026-10-06`**
(commit `be8f35db` on `frontend_refine_kartik`).

```bash
git checkout baseline-2026-10-06            # look at the old version
git diff baseline-2026-10-06 -- frontend/   # see everything that changed in the site
git checkout -b my-branch baseline-2026-10-06   # build on the old version instead
```

## Do these yourself

1. **Revoke the Upstox token.** `backend/upstox_token.json` held a live access token
   and was committed to git. It is no longer tracked, but it is still in the
   history. Revoke it in the Upstox developer console and sign in again with
   `python -m stocksense upstox-login`.
2. **Run `backend/schema.sql`** in Supabase → SQL Editor. It adds the new columns
   (52-week range, P/B, dividend yield, industry, ISIN, score coverage) and turns on
   read-only row-level security for the anon key. Until then the pipeline skips those
   columns and warns.
3. **Rename the secrets in your `.env` files.** The service key was called
   `NEXT_PUBLIC_SUPABASE_SERVICE_KEY`; anything prefixed `NEXT_PUBLIC_` can end up in
   the browser bundle. Use `SUPABASE_SERVICE_KEY` (backend) and `SUPABASE_ANON_KEY`
   (frontend), as in the `.env.example` files. Old names still work in the backend.
   If the service key was ever deployed with that prefix, rotate it in Supabase.
4. **Turn on CI and the scheduled pipeline (optional).** The workflow files are in
   `docs/github-workflows/` because the access token used tonight can't push to
   `.github/workflows/` (it lacks the `workflow` scope). Move them with
   `mkdir -p .github/workflows && git mv docs/github-workflows/*.yml .github/workflows/`
   and push from an account whose token has that scope. Then add repository secrets
   `SUPABASE_URL` and `SUPABASE_SERVICE_KEY`; `pipeline.yml` refreshes prices and fundamentals every weekday
   at 17:00 IST and ownership data on Sundays; you can also start it by hand from the
   Actions tab. `ci.yml` lints, type-checks, builds and tests every pull request.
5. **Keep Supabase awake.** Free projects pause after a week without traffic. The
   site falls back to the snapshot when that happens, but the scheduler should run
   daily (`python -m stocksense scheduler`) to keep data fresh.

## Backend

Before: ten standalone scripts, each with its own copy of env loading and
Supabase setup, and three different copies of the scoring formula.

After: one package, `backend/stocksense`, with a single CLI
(`python -m stocksense <job>`). See `backend/README.md`.

Bugs fixed along the way:

| Bug | Effect | Fix |
|---|---|---|
| Yahoo's `debtToEquity` is a percentage (15.3 = 0.153×) but was used as a ratio | Almost every non-bank stock got a debt score of 0 | Converted in `sources/yahoo.py` |
| A score was only stored when all six metrics existed | ~5 of 2,390 stocks had a score | Missing metrics re-weight the rest; need 4 of 6 |
| Three copies of the scoring formula disagreed | Same stock, different scores by script | `scoring.py` is the only copy (frontend mirrors it in `lib/scoring.ts`) |
| Upstox WebSocket decoder used v2 field numbers | The realtime feed never produced a price | New v3 decoder (`sources/upstox_feed.py`) with tests |
| Realtime job wrote to the database once per tick, inside the loop | Thousands of redundant writes | Buffers and writes once per second |
| Upstox quote job stored absolute change as `change_pct` | Wrong % changes | Computes % from previous close |
| No rate limiting against Yahoo | 1,700 of 2,600 stocks failed with HTTP 429 | Shared rate limiter + back-off |
| Scheduler used the machine's local time for IST market hours | Wrong run times outside India | Times converted from Asia/Kolkata |

## Frontend

Before: every URL rendered the landing page component with an `initialPage` flag,
all data was hard-coded, and styles were 31 KB of hand-written CSS plus inline styles.

After:

* Real App Router structure — `app/(app)/…` pages share one layout.
* One data layer (`lib/data/`) reading Supabase on the server, cached 30 s for
  prices and 5 min for fundamentals, falling back to `data/snapshot.json`.
* New design system on Tailwind v4 tokens; light, number-first, sector-aware gauges.
* Pages that were mock-ups now use real data: dashboard, screener (all ~2,600
  stocks, URL-based filters), stock report cards with real price charts, matched
  picks (filters real stocks by your profile).
* Prospectus scanner actually reads uploaded PDFs.
* Paper trading rewritten as a pure reducer (`lib/paperTrading.ts`) — cash was
  being changed inside a React state updater (runs twice in dev), and two of the
  six missions could never be completed.
* Removed: the canvas constellation and custom cursor (heavy, and the cursor hid
  the real pointer), the unused `/mf` route, `@supabase/supabase-js` on the client.
* `npm run dev` from the repo root used `--prefix`, which made Next look for its
  config in the wrong folder and silently skip Tailwind. Root scripts now `cd frontend`.
